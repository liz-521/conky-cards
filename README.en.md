**Conky floating cards for system monitoring & AI token usage — two lightweight desktop cards.**

Two always-on-top cards (~46MB total, ~7% of an Electron equivalent): one for the machine (CPU/RAM/GPU/VRAM/disk/network), one for AI usage (today's tokens, 5h rolling window, time-to-first-token, 7-day trend). Everything is controlled from a single zenity menu: scaling, opacity, position memory, click-through.

| Card | Contents |
|---|---|
| System | CPU load·freq·temp, RAM+swap, GPU temp·util·power·**PCIe link·compute procs**, VRAM, root disk, 60s CPU graph, daily traffic, live net speed, busiest process |
| AI tokens | Today's total, **5h rolling window**, input/output split, **median time-to-first-token**, request count & top model, progress bar vs 7-day peak, **7-day mini bar chart** |

Values turn yellow (warning) then red (critical) past thresholds (Nord-style theming); temperature/memory/disk/token-peak alerts also fire desktop notifications (rate-limited).

## Features

- **Light**: two conky processes + one python every 4s/15s — ~46MB total, no Electron, no browser engine
- **Stepless scaling**: drag a slider for any size from 0.70× to 2.00× (conky reads config only at startup, so the card "blinks" once into its new size — that's the architectural ceiling); auto-relayout prevents off-screen/overlap after resizing
- **Theming**: Nord / Gruvbox / Dracula / Catppuccin Mocha, one-click switch (drop a `.conf` in `themes/` to add your own)
- **Opacity levels**: five alpha steps plus a "glass" mode (fully transparent background, solid text)
- **Click-through**: conky has no such feature — this project implements it via the XShape extension (empties the window's input region), zero resident processes; mouse events pass straight through, Super+drag still moves the cards
- **Graceful degradation**: no NVIDIA GPU → GPU/VRAM lines auto-hide; no AI CLI database → token card shows a hint instead of crashing; NIC name auto-detected
- **Self-diagnosis**: `conky-doctor` checks every dependency and reports which features will light up on your machine

## Install

Dependencies: `conky-all`, `python3`, `zenity`, `x11-utils` (xwininfo), `libnotify-bin` (notify-send), CJK fonts `fonts-noto-cjk` + `fonts-wqy-microhei` (block characters), optional `python-xlib` (click-through) and `nvidia-smi` (NVIDIA GPU).

```bash
sudo apt install conky-all zenity x11-utils libnotify-bin fonts-noto-cjk fonts-wqy-microhei
pip install python-xlib        # for click-through

git clone https://github.com/liz-521/conky-cards.git
cd conky-cards
./install.sh                   # idempotent; run again safely
```

What gets installed: config → `~/.config/conky-ai-cards/`, commands → `~/.local/bin/`, an app-menu entry "悬浮卡" + autostart. Uninstall with `./uninstall.sh`.

## Usage

Everything goes through the app-menu entry **“悬浮卡控制”** (or run `conky-ctl`):

| Action | Description |
|---|---|
| On/Off | Toggle both cards (`conky-card token/system` keeps just one) |
| Scale | ±10% steps, or the stepless slider (0.70–2.00) |
| Remember position | After Super+drag, persist the position across reboots (two-pass calibration cancels conky's gap rounding) |
| Opacity | 255/230/195/153/102 + **glass** (transparent background, solid text) |
| Click-through | Mouse events pass through the cards to windows below (auto-restored after restarts) |
| Theme | Nord / Gruvbox / Dracula / Catppuccin |

To change what the cards show, edit `sys-body.py` (system) and `zcode-today.py` (tokens) in the config dir — all card content is generated by python; the lua files only manage windows.

## Data sources

- System card: `/proc`, `nvidia-smi`, `ps` — purely local
- Token card: the local usage DB of ZCode CLI (`~/.zcode/cli/db/db.sqlite`, read-only with `PRAGMA query_only=ON`; all SQL is literal + `?`-bound). Note the **official quota lives server-side**; the local DB only has token counts, so the "5h window" is a local reference
- Daily traffic: `/proc/net/dev` cumulative − midnight baseline (auto-maintained)

## Architecture & pitfalls (the interesting part)

**Lua only manages windows; all content is generated by python.** Each lua file contains a single `${execpi N python3 ...}` whose output conky re-parses as conky text — python decides thresholds and emits `${color}` / `${cpubar}` objects directly.

Why this detour? Because **conky 1.19.6's `if_match` with `${color}` inside branches is unreliable under X rendering**: on the same card one line turns red while another doesn't; the same line flips between renders; yet `conky -t` console mode works flawlessly. A T/F-marker experiment proved branch selection was correct — only the color objects failed. Unfixable, so we route around it.

Other pitfalls we hit and documented (read before hacking):

- No `$` or `{` allowed inside `execi`/`execpi` arguments (the conky parser eats them)
- `execibar` without explicit size fills the whole line and pushes values off-card; `execigraph`'s size argument parsing is outright broken in 1.19.6 (commands must also be a single word) — that's why the GPU trend uses character blocks instead
- `own_window_argb_value` controls the opacity of the **whole window including text**; `own_window_transparent` only zeroes the **background** — "transparent background + solid text" needs both
- conky's `gap_y` differs from the actual window y by ~5px of font padding; position memory needs two-pass calibration to converge
- Unicode block characters (U+2581–88) are missing from Noto Sans CJK — use WenQuanYi; XFT spacing keeps blocks from forming a perfect staircase
- XShape click-through state dies with the window — every restart must re-apply it (`start-all.sh` does this automatically)
- Undecorated windows with `below` hint go invisible under GNOME (covered by the wallpaper window) — avoid

## Known limitations

- Token features depend on ZCode CLI's DB schema (`model_usage` / `turn_usage`); other AI CLUs need adapter work
- Click-through requires an X11 session (XShape doesn't affect native Wayland windows)
- Block-character charts have inter-block gaps (XFT rendering), data-correct but not a perfect staircase
